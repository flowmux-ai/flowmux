# Flowmux 0.13.0

Flowmux 0.13.0 adds agent-state diagnostics, Linux terminal process isolation,
and clearer handling of unexpected terminal exits. It also improves how agent
activity, pending input, retry waits, and completed responses are tracked.
These notes cover the final changes since v0.12.1.

[한국어 릴리스 노트](https://github.com/flowmux-ai/flowmux/blob/v0.13.0/docs/releases/0.13.0.ko.md)

## Agent activity and diagnostics

- **See which agents need attention.** The Agents side panel and compact bar
  show live counts for input, review, waiting, and unconfirmed states. Counts
  represent agents, not individual requests; reading a notification does not
  resolve a pending input request.
- **Distinguish retry waits from requests for user input.** Recognized automatic
  continuation displays “Waiting to retry”; a canceled continuation can display
  “Usage limit reached; input required.” Unknown retry context remains unknown.
- **Inspect the reason behind a state.** The new `agents --explain` command
  reports status evidence, pending waits, response outcome, and observed child
  work. Filter by tab surface or request JSON for troubleshooting and automation:

  ```sh
  flowmux agents --explain
  flowmux --json agents --explain
  flowmux agents --explain --surface <surface-uuid>
  ```

- **Diagnose hook delivery more precisely.** `flowmux hooks doctor` now includes
  current agent evidence. Opt-in `FLOWMUX_AGENT_TRACE=1` tracing separates hook
  transport from state-application decisions. A successful hook exit or RPC
  acknowledgment alone is not proof that a displayed state was applied.
- **Use recognized terminal output as additional evidence.** Bounded program
  snapshots supplement hooks and process observations, including recognized
  retry and activity signals. Editable input and display metadata are excluded
  from status signals. This does not imply support for every agent or terminal UI.

The list retains its existing click-to-terminal interaction. This release does
not add a separate agent-details popup. Child information is an observation
ledger, not a complete inventory of every child process. A completed response
does not mean the agent's work has been independently verified as successful.

## More reliable states and notifications

- Preserve unresolved approval, question, quota, authentication, and API waits
  independently. Resolving one wait no longer clears unrelated pending work.
- Keep response outcomes separate from ongoing activity and child work, reducing
  premature completion and agents that remain incorrectly marked as working.
- Correlate completion notifications with response boundaries and deduplicate
  input notifications by pending request.
- Prevent delayed events, final timer repaints, and unrelated tool completions
  from reopening or incorrectly clearing waits.
- Keep agent-row widgets stable across status updates so clicks, keyboard focus,
  and navigation remain reliable in both list layouts.

## Terminal isolation and unexpected exits

- **Linux: isolate terminal tabs in systemd scopes.** With the user service
  manager available, `process_isolation: "auto"` creates a separate scope for
  each terminal tab. Flowmux continues without scope isolation when unavailable.
- **Linux: configure per-tab memory limits.** `pane_memory_high` and
  `pane_memory_max` accept values such as `64M` or `4G`. Limits are disabled by
  default and apply to new scopes; a hard limit also disables swap for that
  scope. `child_oom_score_adj` defaults to 500 for children running without their
  own scope, and can be set to 0 to disable the adjustment.
- **Understand unexpected terminal deaths.** A queued, tab-specific dialog
  explains the observed termination and offers **Keep tab** or **Close tab**
  (**Close workspace** when appropriate). OOM attribution uses available
  evidence rather than treating every killed process as an OOM event.
- Preserve exit reporting across tab tear-off and queued events. Closing an
  affected tab dismisses its obsolete termination dialog, so it cannot block
  later window-close actions.
- Improve child startup coordination, signal-exit reporting, and graceful GUI
  signal handling.

Scope isolation and memory settings are Linux-only; they do not impose limits
on macOS. Restart Flowmux after changing `process_isolation`. See the
[configuration reference](https://github.com/flowmux-ai/flowmux/blob/v0.13.0/docs/configuration.md)
for prerequisites and configuration details.

## Editor, browser, and native stability

- Recover and close editors more reliably after repeated renderer exits, drain
  recovery writes without blocking GTK, and initialize macOS editor zoom from
  navigation state.
- Release browser script completions after host deadlines instead of retaining
  them indefinitely.
- Bound Agent Office sprite-resampling buffers and improve cleanup during
  repeated view creation and destruction.
- Unwind macOS native menu tracking when the last window closes.
- Expand regression coverage for process isolation, terminal deaths, editor
  recovery, agent hooks, program-state observations, and native resource churn.

## Updating and downloads

- Update the application and CLI together, then restart Flowmux when convenient
  to load the new runtime. Existing windows continue to run their previous build.
- Linux x86_64 downloads include a tarball and Debian package. macOS Apple
  Silicon downloads include a DMG; drag **Flowmux.app** to **Applications**.
- Every binary download has a `.sha256` sidecar. Matching source is linked below.
- The macOS preview still requires Homebrew runtime libraries under
  `/opt/homebrew`; it is not a standalone bundle. It is ad-hoc signed, not
  Developer ID signed or notarized. Intel macOS binaries are not provided.
- macOS CI and release builds use GTK 4.22.3 with libadwaita 1.9.3 because GTK
  4.24.1 triggers a native popup lifecycle assertion in the smoke tests. The DMG
  uses the installed Homebrew libraries at runtime, so this build setting does
  not fix or replace an affected local GTK installation.
