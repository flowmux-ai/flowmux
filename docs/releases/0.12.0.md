# Flowmux 0.12.0 — browser work you can see and verify

Your agent can do more of the web work beside your terminal: fill and check forms, handle files and dialogs, interact with canvases, and save visual evidence. A new task bar keeps the current step, user handoff and results visible in the same tab.

## Browser examples: inspect → act → verify → capture

### Fill a form, then check what actually happened

Try asking your agent: **“Fill the project, reviewer and release track. Check all three fields, prepare the summary, and confirm that ‘Ready to review’ appears.”**

![Three form fields checked in the terminal, with Form checked and Result confirmed cards in the browser](https://raw.githubusercontent.com/flowmux-ai/flowmux/v0.12.0/docs/releases/0.12.0/browser-form.jpg)

The new `form` command checks each field and reports which passed. It does not send a submit command. A separate click can wait for an expected page result; Flowmux distinguishes **input delivered** from **result confirmed**. In this example, all three fields passed and the requested summary appeared.

The task bar shows the task name and current step. **Take control**, **Continue** and **Stop** let you coordinate with the agent; **Results** opens the task's forms, captures, downloads and action outcomes. A delivered action is never silently repeated because its result took too long to appear.

### Upload a file, verify its download, and draw on a canvas

Try: **“Choose the sample CSV, check that three rows loaded, download the checklist, and draw a route on the canvas. Save the finished page.”**

![Completed browser task with a CSV uploaded, a completed download and a route drawn using native pointer input](https://raw.githubusercontent.com/flowmux-ai/flowmux/v0.12.0/docs/releases/0.12.0/browser-files-canvas.jpg)

This capture follows a real file-picker selection, a download that reached `complete`, and three native pointer drags. The downloaded CSV was compared byte-for-byte with the original. The [full document capture](https://raw.githubusercontent.com/flowmux-ai/flowmux/v0.12.0/docs/releases/0.12.0/demo-full-page.png) includes the form, imported file and drawn route without manually scrolling and stitching screenshots.

The website in these examples is a [local demonstration page](https://github.com/flowmux-ai/flowmux/blob/v0.12.0/docs/releases/0.12.0/demo.html), with fictional details and no external submission. The UI and command results are actual captures, not interface mockups.

### More of the browser workflow is supported

| What you want to do | What 0.12.0 adds or improves |
| --- | --- |
| Work with ordinary websites and rich editors | Native text editing, keys, clicks, double-clicks and hover; coordinate input and dragging for canvas controls. Hidden, disabled, covered or stale targets are rejected where applicable. |
| Find the right control with less output | Search by role, name, label or text. Scoped and compact snapshots keep element references while reducing duplicate output. Open Shadow DOM and same-origin frames are supported. |
| Keep work in the intended tab | Pin commands to a tab surface. Popup tabs retain their native browsing context. Stale references fail instead of selecting a replacement element. |
| Respond to website prompts | Inspect and answer page alerts, confirmations and prompts by their dialog ID. Select upload files within an explicit allowed directory. |
| Bring files back into the project | Set a tab's download directory, inspect progress and completion, or cancel a download. Starting a download and finishing it are distinct states. |
| Save evidence or a short walkthrough | Capture the viewport, a full document or one referenced element as PNG. Record sampled viewport frames to a silent H.264 MP4 with `ffmpeg`/`libx264`. |
| Review audio or video | Play, pause, seek, mute and read playback status. Playback and seek commands check the resulting media state. |
| Understand a blocked action | Live diagnostics report backend and input/capture support. Explicit waits and action receipts help distinguish a pending dialog, an unknown outcome and a confirmed condition. |

For example, once your agent has selected the browser pane:

```sh
flowmux browser find "$PANE" --role button --name Save --exact --compact
flowmux browser screenshot "$PANE" /tmp/page.png --full-page
flowmux browser record "$PANE" /tmp/walkthrough.mp4 --seconds 5 --fps 5
```

See the [browser guide](https://github.com/flowmux-ai/flowmux/blob/v0.12.0/docs/browser-workflow.md) and [CLI skill](https://github.com/flowmux-ai/flowmux/blob/v0.12.0/.agents/skills/flowmux-browser/SKILL.md) for tab/task ownership and complete examples.

On a new version's first launch, existing Flowmux CLI and Team skills are refreshed automatically, including known legacy/shared user copies. Modified files are backed up. The Skills page also adds Gemini support, separate CLI/Team installation, destination paths, shared-copy warnings and **Check Team setup**. “Up to date” means the files match this app's bundle; your agent may need to reload its skills or start a new session to use them.

## Everyday improvements beyond the browser

- **Resume the agent you intend to use.** Saved-session selection gains agent
  choice and an explicit YOLO resume option. Login-shell PATH is retained when
  resuming selected agents on macOS.
- **Team work with fewer interruptions.** Gemini CLI and Antigravity CLI can lead
  teams alongside Claude Code and Codex. Workers still use Claude Code or Codex.
  Idle workers are reused, observed usage limits inform routing, and recovery,
  quotas and task deadlines are handled more consistently. YOLO worker mode is
  an explicit option, not a new default.
- **Usage is easier to read.** Usage bars are 50% wider; pinned limits and Claude
  model limits stay distinct.
- **Terminal context stays useful.** Hidden viewport text is preserved, title
  updates are bounded, and long file paths are recognized more reliably.
- **macOS polish.** Installer updates preserve running sessions and the stable
  app path; browser file pickers, detached inspector windows and tab drag previews
  receive focus and layering fixes.
- **Quit confirmation reliability.** Responding to or dismissing the quit dialog
  no longer tries to close it a second time on newer libadwaita runtimes. Linux
  release binaries are built on Ubuntu 24.04 to retain the supported baseline.
- **Dependency maintenance.** Tokio was updated to address the advisory handled
  during this release cycle.

## Install and platform notes

Download the Linux x86_64 `.deb` or tarball, or the Apple Silicon `.dmg`, from **Assets** below. SHA-256 files accompany each package. Existing supported local installs can use the in-app update controls; packaged installs may direct you to their package manager or release page. See [setup](https://github.com/flowmux-ai/flowmux/blob/v0.12.0/docs/setup.md).

- **macOS preview:** drag `Flowmux.app` from the DMG to Applications. Homebrew
  `gtk4`, `libadwaita` and `vte3` under `/opt/homebrew` remain required. The app is
  ad-hoc signed, not notarized or Developer ID signed; Gatekeeper may block it.
  This is not a standalone or Intel Mac package.
- **Linux input:** X11 uses native input. Wayland input requires a compatible
  RemoteDesktop portal and your explicit desktop-control consent; keep the
  target window focused. Portal support varies by desktop.
- **Capture/media:** full-document capture on macOS requires macOS 15+ and has a
  64 MiB bitmap limit. Video/WebGL layers can be absent from document snapshots.
  MP4 recording is sampled and silent; media playback depends on installed codecs.
- **Scope:** cross-origin frames and closed shadow roots are not exposed.
  CDP network mocking/device emulation and browser-cookie import are not supported.
  A confirmed page condition does not independently prove server-side persistence.
