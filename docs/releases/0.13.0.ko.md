# Flowmux 0.13.0

Flowmux 0.13.0은 에이전트 상태 진단, Linux 터미널 프로세스 격리,
비정상 종료 안내를 추가합니다. 에이전트의 실행 상태, 입력 대기, 재시도 대기,
응답 완료를 추적하는 방식도 개선했습니다. 이 문서는 v0.12.1 이후 최종적으로
반영된 변경사항을 설명합니다.

[English release notes](https://github.com/flowmux-ai/flowmux/blob/v0.13.0/docs/releases/0.13.0.md)

## 에이전트 상태와 진단

- **조치가 필요한 에이전트를 요약합니다.** Agents 사이드 패널과 하단 바에
  입력 필요, 검토 필요, 대기, 미확인 상태의 수를 표시합니다. 개별 요청 수가
  아닌 에이전트 수이며, 알림을 읽는 것만으로 입력 대기가 해제되지는 않습니다.
- **재시도 대기와 사용자 입력 대기를 구분합니다.** 자동 재개가 관측되면
  `Waiting to retry`, 자동 재개 취소가 확인되면
  `Usage limit reached; input required`로 표시합니다.
  재시도 방식을 확인할 수 없으면 미확인 상태를 유지합니다.
- **상태 판단의 근거를 조회할 수 있습니다.** 새 `agents --explain` 명령으로
  상태 근거, 미해결 대기, 응답 결과, 관측된 하위 작업을 확인합니다.
  특정 탭만 선택하거나 JSON으로 출력할 수 있습니다.

  ```sh
  flowmux agents --explain
  flowmux --json agents --explain
  flowmux agents --explain --surface <surface-uuid>
  ```

- **hook 전송과 상태 반영을 구분해 진단합니다.** `flowmux hooks doctor`에
  현재 에이전트 상태의 근거가 추가됐습니다. `FLOWMUX_AGENT_TRACE=1`을 사용하면
  hook 전송과 상태 반영 결정을 별도로 추적할 수 있습니다. hook 프로세스의
  정상 종료나 RPC 응답만으로 화면 상태가 반영됐다고 판단하지 않습니다.
- **인식 가능한 터미널 출력을 추가 근거로 활용합니다.** 크기가 제한된 프로그램
  상태 스냅샷으로 재시도·활동 신호를 수집해 hook과 프로세스 관측을 보완합니다.
  편집 중인 입력이나 표시용 메타데이터는 상태 신호에서 제외합니다.
  모든 에이전트나 터미널 UI를 인식한다는 의미는 아닙니다.

에이전트 행을 클릭해 터미널로 이동하는 기존 동작은 유지됩니다. 별도의 상세
아이콘·팝업을 새 기능으로 제공하는 릴리스는 아닙니다. 하위 작업 정보는 관측된
기록이며 모든 자식 프로세스의 완전한 목록이 아닙니다. 응답 완료 표시는 작업의
성공 여부를 Flowmux가 독립적으로 검증했다는 뜻이 아닙니다.

## 상태와 알림의 정확성 개선

- 승인·질문·사용량 제한·인증·API 오류 대기를 각각 유지합니다. 하나를 해결해도
  다른 미해결 대기가 잘못 해제되지 않도록 했습니다.
- 응답 결과와 현재 실행·하위 작업을 분리해, 성급한 완료 표시와 완료 후에도
  계속 작업 중으로 남는 문제를 줄였습니다.
- 응답 경계를 기준으로 완료 알림을 연결하고, 미해결 요청을 기준으로 중복
  입력 요청 알림을 억제합니다.
- 지연된 이벤트, 마지막 타이머 화면 갱신, 관계없는 도구 완료가 대기를 다시
  열거나 잘못 해제하지 않도록 했습니다.
- 상태 갱신 시 에이전트 행 위젯을 유지해 사이드 패널과 하단 바의 클릭,
  키보드 포커스, 이동 동작을 안정화했습니다.

## 터미널 격리와 비정상 종료 대응

- **Linux 탭별 systemd scope 격리:** 사용자 서비스 관리자를 사용할 수 있으면
  기본값인 `process_isolation: "auto"`에서 탭마다 별도 scope를 만듭니다.
  사용할 수 없는 환경에서는 scope 격리 없이 실행을 계속합니다.
- **Linux 탭별 메모리 제한:** `pane_memory_high`, `pane_memory_max`에
  `64M`, `4G` 등의 값을 지정할 수 있습니다. 제한은 기본적으로 꺼져 있고
  새 scope에 적용됩니다. 최대 메모리 제한을 지정하면 해당 scope의 swap도
  비활성화됩니다. 자체 scope 없이 실행되는 자식 프로세스의
  `child_oom_score_adj` 기본값은 500이며, 0으로 설정하면 조정을 끕니다.
- **비정상 종료 안내:** 종료된 탭의 원인을 설명하고 **Keep tab**, **Close tab**을
  선택하는 대화상자를 표시합니다. 마지막 탭 등 해당 상황에서는
  **Close workspace**를 표시합니다. OOM 여부는 확보된 근거로 판단하며,
  강제 종료를 모두 메모리 부족으로 단정하지 않습니다.
- 탭을 별도 창으로 분리하거나 종료 이벤트가 대기열에 쌓여도 종료 안내를
  유지합니다. 해당 탭을 닫으면 오래된 종료 대화상자도 닫아, 이후 창 닫기를
  막지 않도록 했습니다.
- 자식 프로세스 시작 순서 제어, 시그널 종료 전달, GUI 종료 시그널 처리를
  개선했습니다.

scope 격리와 메모리 설정은 Linux 전용이며 macOS에는 제한을 적용하지 않습니다.
`process_isolation`을 바꾸면 Flowmux를 재시작해야 합니다. 세부 조건은
[설정 문서](https://github.com/flowmux-ai/flowmux/blob/v0.13.0/docs/configuration.md)를 참고하세요.

## 에디터·브라우저·네이티브 안정성

- 에디터 렌더러가 반복 종료될 때 복구와 닫기를 개선하고, GTK를 막지 않도록
  복구 쓰기를 처리합니다. macOS 에디터 확대율 초기화도 수정했습니다.
- 브라우저 스크립트가 호스트 제한 시간을 넘기면 완료 처리 자원을 해제합니다.
- Agent Office 이미지 리샘플링 버퍼의 크기를 제한하고, 화면을 반복 생성·제거할
  때 자원 정리를 개선했습니다.
- macOS의 마지막 창을 닫을 때 네이티브 메뉴 추적을 정리합니다.
- 프로세스 격리, 터미널 종료, 에디터 복구, 에이전트 hook, 프로그램 상태 관측,
  네이티브 자원 반복 생성·정리에 대한 회귀 검사를 확대했습니다.

## 업데이트와 배포 파일

- 앱과 CLI를 함께 업데이트하고, 편한 시점에 Flowmux를 재시작해 새 런타임을
  사용하세요. 기존 실행 창은 이전 빌드로 계속 동작합니다.
- Linux x86_64는 tarball과 Debian 패키지, macOS Apple Silicon은 DMG를 제공합니다.
  DMG에서 **Flowmux.app**을 **Applications**로 이동해 설치합니다.
- 각 바이너리 파일에 `.sha256` 체크섬 파일을 제공합니다. 대응 소스는 아래에 연결했습니다.
- macOS 프리뷰는 `/opt/homebrew`의 Homebrew 런타임 라이브러리가 필요합니다.
  독립 실행 번들이 아니며 ad-hoc 서명만 적용돼 있습니다. Developer ID 서명·공증 및
  Intel macOS 바이너리는 제공하지 않습니다.
- macOS CI와 릴리스 빌드는 GTK 4.24.1의 네이티브 팝업 수명주기 검사 실패를 피해
  GTK 4.22.3과 libadwaita 1.9.3을 사용합니다. DMG는 실행 시 설치된 Homebrew
  라이브러리를 사용하므로, 이 빌드 설정이 사용자의 GTK 설치를 교체하거나 해당
  GTK 문제 자체를 해결하지는 않습니다.
