# Flowmux 브라우저 사용성과 기능 확장 재검토

검토일: 2026-10-25. 코드 기준: `main`, `51160b6824632cc6b37cac4430297e1f40f120ef`, 버전 `0.11.4`.

이 문서는 P1-1~P1-5 구현 이후의 분석이다. 이전의 구현 전 우선순위를 대체한다. 공개 사용자 문서·SDK 계약과 현재 소스를 비교했으며, 경쟁 제품을 설치해 동일 사이트에서 성능이나 보안 강도를 측정한 결과는 아니다. 아래의 제안·코드상 경계 사례·이미 검증된 기능을 구분한다.

**기존 P1 구현은 완료로 유지한다. 아래의 확장 제안은 이전 작업의 미완료 목록이 아니다.** 작업 안내·결과 카드·폼 묶음 입력·frame/shadow 결과 조건·파일 상태 연결을 새 이름으로 다시 완료 조건에 추가하지 않는다.

## 0. 완료 범위와 후속 후보의 구분

| 구분 | 해당 범위 | 처리 기준 |
| --- | --- | --- |
| 완료 유지 | P1-1 작업 상태 안내, P1-2 결과 카드, P1-3 폼 묶음 입력·항목별 검증, P1-4 same-origin iframe/open shadow 결과 조건, P1-5 파일 상태 연결 | 확장 아이디어가 생겨도 원래 작업을 미완료로 바꾸지 않음 |
| 결함 확인 후보 | 진행 중 다운로드 카드의 이력 초과 처리, 폼 추가 조건 표시, macOS 문서 가시성과 진단의 불일치 | 기존 계약 위반을 재현하면 별도 결함으로 수정하고 해당 재현 통과로 닫음. 재현되지 않으면 확인 범위와 한계를 기록하고 필수 수정 목록에서 제외 |
| 기존 기능의 선택적 UX 확장 | P2-1 중 새 대기 안내, P2-2 프로필 선택·작업 시작 UI, P2-5 폼 오류 상세 UI | 기존 기능 미완료로 취급하지 않고, 실제 사용 불편과 별도 범위가 확인될 때 착수 |
| 별도 신규 기능 후보 | P2-3 결과 영구 보관, P2-4 구조화 추출, P2-6 SDK, P2-7 템플릿, P2-8 미디어 확장 | 모두 구현해야 하는 잔여 작업이 아님. 선택한 기능의 완료 기준만 적용 |
| 기술 조사 후보 | Wayland native 입력, cross-origin frame, 사용자와 병행 입력, 실제 화면·오디오 녹화 | 구체적인 차단 사례가 있을 때 제한된 실증으로 지원 가능 범위를 결정. 기존 P1 종료 조건에 추가하지 않음 |

보안 항목도 이미 반영된 보호 기능을 반복 개발하는 목록이 아니다. 재현된 결함은 별도 수정하고, 결과 저장·추출 등 신규 기능에 필요한 보호 조건은 그 기능의 완료 기준에 포함한다. 아래 P2 번호는 비교 검토용 식별자로 유지하며, 전체 구현을 확정한 작업 목록을 뜻하지 않는다.

## 1. 현재 구현과 남은 차이

| 영역 | 현재 제공 | 추가 개선 후보 |
| --- | --- | --- |
| 기본 입력 | native click/dblclick/hover/drag/press/type, fill/select/check, 제한된 준비 대기 | 가려진 문서·포커스 이동 안내, 복잡한 편집기의 입력 방식 선택 |
| 탐색·관찰 | role/name/label/text/placeholder, subtree/viewport/interactive 필터, 출력 상한, same-origin iframe/open shadow refs | 재탐색 안내, 중복 후보 선택, 여러 페이지의 표·목록 추출 |
| 작업 제어 | 탭별 task, Take control/Continue/Stop/Clear, 작업 이름·단계·대기 이유·사용자 행동 | 현재 페이지에서 시작하는 GUI 동선, 계정 선택, 다중 탭 작업 묶음, 재시작 복귀 |
| 결과 | receipt, 관련 팝업·PNG·다운로드·파일 선택 결과 카드와 파일/폴더 열기 | 결과 저장·검색·미리보기·내보내기, 진행 중 결과의 수명 보장 |
| 폼 | 1~20개 ref 기반 fill/select/check, verified/invalid/failed/not_run, 개별 재입력 가능 | 항목별 오류를 UI에서 펼쳐 보기, 포맷팅 입력의 검증 규칙, native 편집 지원 |
| 결과 조건 | URL/값/상태/변화/팝업 준비/다운로드 완료, `Element`로 원래 frame/shadow 노드 검증 | 조건 조합, 비동기 필드 오류와 추가 결과 조건의 별도 표시 |
| 계정·파일 | 프로필별 저장소, 한글 이름 충돌 방지, Linux 저장 실패 시 별도 임시 저장소와 경고, 업로드 루트 검증 | 불변 프로필 ID, 관리 UI, 안전한 이름 변경, 로그인 복귀, 결과 파일 보관 정책 |
| 미디어 | play/pause/seek/mute, PNG, 최대 60초·10fps의 무음 snapshot MP4 | 볼륨·속도·제공되는 자막, 실제 화면·오디오 캡처의 별도 검증 |
| 연동 | CLI/IPC, Flowmux CLI 스킬, 별도 임시 WebDriver 창 | 작은 SDK, 안정적인 오류 코드, 검토 후 저장하는 반복 작업 |

소스: [CLI](../crates/flowmux-cli/src/main.rs), [프로토콜](../crates/flowmux-ipc/src/protocol.rs), [작업 UI](../crates/flowmux/src/ui/browser_control.rs), [명령 실행](../crates/flowmux/src/ui/window/browser_commands.rs), [사용 계약](browser-workflow.md), [WebDriver 범위](webkit-automation.md).

다음 의미는 유지한다.

- `form`은 제출 명령을 보내지 않고 자동 재시도하지 않는다. 다만 사이트의 input/change 핸들러가 요청을 전송할 수 있어 트랜잭션이나 무부작용 보장은 아니다.
- `outcome_confirmed`와 업로드의 `condition_observed`는 지정한 사이트 조건의 관측이다. 서버 영구 저장이나 인과관계의 독립 검증은 아니다.
- task ID는 탭의 협력적 제어권이다. 계정 격리·비밀 토큰·에이전트 인증으로 취급하지 않는다.
- 결과는 세션 내 최근 20개, 관찰 이벤트는 최근 64개다. 작업 설명은 호출자가 제공하며 자동 추정된 업무 진행률이 아니다.
- 부분 snapshot도 ref 집합을 교체한다. 기존 selector 조건은 최상위 문서 의미를 유지하고, frame/shadow 검증에는 `Element`를 사용한다.

## 2. 공개 기술과 비교한 판단

ego(lite)의 공개 SDK는 `d392204d1ea1a8027a591ab2b0129c2e11d85f26` 기준으로 확인했다. 일반 안내와 SDK v2의 참조 수명 설명이 다르므로, 한쪽 설명을 모든 배포판의 보장으로 확대하지 않는다.

[Space](https://lite.ego.app/document/en/docs/space), [Native API](https://github.com/citrolabs/ego-lite/blob/d392204d1ea1a8027a591ab2b0129c2e11d85f26/docs/native-bindings-api.md) | 제어 UI는 이미 있으나 작업 생성·프로필 선택·관련 탭 관리를 사용자가 한 번에 수행하는 동선이 부족하다. 작업 탭 분리와 쿠키 격리를 별도 계약으로 정의한다. |

| 복잡한 페이지 | 엔진 기반 cross-origin frame 관찰을 설명하지만 snapshot 안내에는 sandboxed frame·canvas·이미지 텍스트 한계도 있다. | 여러 단계 조합 | TaskSpace/Page API, 페이지별 이벤트와 network-idle, 구조화된 오류 계약을 제공한다. 공개 성능 수치는 공급자 측 평가다. 모델·사이트·로그인·실패 판정이 같은 실험 없이 Flowmux가 몇 배 느리다고 결론 내리지 않는다. 프로필 상속·작업별 저장소의 실제 동기화 범위도 공개 설명만으로 보안 격리를 확정할 수 없다.

## 3. 별도로 재현 확인할 결함 후보

다음 두 항목은 **소스에서 도출한 경계 사례이며 이 검토에서 새로 런타임 재현한 버그는 아니다.** 작은 재현 테스트로 수정 필요 여부를 판정하며, 이를 이유로 P1 전체를 다시 미완료 처리하지 않는다.

| 항목 | 코드 근거와 영향 | 최소 보완·완료 기준 |
| --- | --- | --- |
| 진행 중 결과의 수명 | `BrowserControl::result`는 20개 초과 시 오래된 카드를 제거하고, `download_result`는 기존 카드가 있는 download ID만 갱신한다. 긴 작업에서는 진행 중 다운로드가 밀려 완료 카드로 돌아오지 않을 수 있다. | 표시 이력과 진행 중 ID 추적을 분리하거나 진행 중 카드를 고정한다. 다운로드 시작 뒤 20개 이상 결과를 생성해도 완료 파일 경로와 상태가 도착해야 한다. 업로드 조건 관측에도 같은 수명 규칙을 적용한다. |
| 폼 검증과 추가 조건 | 결과 카드 생성은 form이면 먼저 항목별 verified 수를 요약한다. 명령에 붙인 receipt의 추가 결과 조건이 미확인인지 별도 표시하지 않는다. | `3/3 입력 검증`과 `추가 조건 미확인`을 함께 표시한다. 필드가 모두 유효해도 expect가 시간 초과하면 업무 확인으로 읽히지 않아야 한다. |

소스: [결과 보관·다운로드 연결](../crates/flowmux/src/ui/browser_control.rs), [폼 결과 카드·receipt](../crates/flowmux/src/ui/window/browser_commands.rs).

macOS에는 별도 현장 관측도 있다. 이전 로컬 검사에서 `document.hidden=true`, `document.hasFocus()=false`인데 `diagnose`의 active/visible/environment_ready는 true였다. 현재 진단은 GTK 매핑·활성 surface·환경 조건을 확인하고 실제 문서 가시성은 확인하지 않는다. 이는 환경 진단과 입력 준비 상태의 차이이며, 이번 변경으로 생긴 회귀라고 확정하지 않는다. 같은 코드의 원격 전체 회귀는 통과했다. 다음 개선은 실제 문서 상태를 진단과 사용자 안내에 연결하고, 가려짐·최소화·탭 전환의 재현을 분리하는 것이다. 입력 준비 시간만 늘리거나 사용자의 다른 창을 강제로 활성화하는 방식으로 감추지 않는다.

## 4. 선택 가능한 확장 후보와 상대 우선순위

기존 P1 번호는 완료 이력으로 남기고 새 범위는 P2로 구분한다. P2-1은 결함 확인과 선택적 안내 확장이 섞인 항목이므로 착수할 때 분리한다. 규모는 일정 약속이 아니라 상대적인 변경 범위다.

| 순서 | 액션 아이템 | 사용자 이점·최소 범위 | 완료 기준 | 규모 |
| --- | --- | --- | --- | --- |
| P2-1 | 결과 신뢰성과 막힘 안내 | 위 경계 사례, 문서 가림, native 권한 요청 대기, 오류 코드와 다음 행동을 결과 화면에 연결 | 진행 중 파일이 이력에서 사라져도 완료 추적. 입력 검증/추가 조건/사용자 권한 대기를 구분. 자동 재전송 없음 | 작음~중간 |
| P2-2 | 현재 탭에서 작업 시작·프로필 선택 | 현재 페이지/새 탭, 기존 프로필/작업용 임시 프로필, 작업 이름을 한 화면에서 선택. 로그인 뒤 원래 작업으로 복귀 | 두 프로필 계정 혼용 없음. 이름 변경 후 로그인 유지. 권한 있는 기존 탭을 조용히 다른 작업에 편입하지 않음 | 중간 |
| P2-3 | 결과 저장·검색·미리보기 | 선택한 작업의 요약·출처·확인 시각·관련 URL·파일을 저장. PNG/PDF/텍스트는 기존 뷰어 재사용. 재시작 후 읽기 전용 복원 | 파일 이동·삭제 표시, 보관/삭제 정책, 민감 URL 제거. 과거 ref·task 제어권·클릭은 자동 복원하지 않음 | 중간 |
| P2-4 | 표·목록의 구조화 추출 | 지정한 열·행을 JSON/CSV로 내보내고 출처 URL·수집 시각·현재 페이지/전체 여부 기록 | 페이지 이동 중 중복 키·누락·중단 위치 표시. 가상 목록을 전체라고 보고하지 않음. 원본 값과 가공 값 구분 | 중간 |
| P2-5 | 폼 실패 수정과 편집기 편의 | 카드에서 항목별 오류 보기, 실패 항목으로 이동, fill/native 방식 명시, 필요한 항목에 별도 검증 조건 | 한글 IME·여러 줄·contenteditable·포맷팅 입력 검증. 실패 뒤 다른 입력 방식으로 무조건 다시 쓰지 않음 | 중간 |
| P2-6 | 작은 SDK·이벤트 대기 | 기존 IPC 위에 surface/task 고정, 구조화 오류, 결과 파싱, sequence 기반 팝업·다운로드 대기 제공 | CLI와 결과 동일. 중간 취소 뒤 다음 단계 미실행. 출력 잘림과 연결 종료 식별. polling 유지로 시작 | 중간 |
| P2-7 | 사용자가 저장하는 반복 절차 | 사이트·입력 파라미터·의미 기반 대상·기대 결과를 검토 후 저장. 실행 전 변경 내용 확인 | 로그인 만료·대상 중복·페이지 변경 시 정지. 비밀번호·쿠키·기존 ref는 템플릿에 저장하지 않음 | 중간 |
| P2-8 | 작은 미디어 확장 | 볼륨·재생 속도·페이지가 제공하는 자막 읽기, 구간별 캡처 | 실제 재생 상태 확인. 자막 없음·코덱/DRM 제약 명시. 자막 생성이나 오디오 녹화로 과장하지 않음 | 작음~중간 |

우선 확인 대상은 3절의 결함 후보다. 기능 확대를 별도로 선택한다면 **작업 시작·계정 선택 → 결과 보관 또는 구조화 추출** 순서를 제안한다. 나머지는 사용 수요가 확인될 때 선택하며, 이 목록 전체를 완료해야 기존 브라우저 개선이 끝나는 것은 아니다. 예약 실행은 이번 범위에 포함하지 않는다.

### 계정 선택에서 지켜야 할 계약

[현재 프로필](../crates/flowmux-browser/src/profile.rs)은 이름을 손실 없이 인코딩하지만 표시 이름과 저장소 identity는 여전히 결합돼 있다. Linux에서는 긴 이름의 인코딩 결과가 파일명 한도를 넘을 수 있다. 관리 UI 도입 시 불변 ID와 표시 이름을 분리하고, 기존 저장소 경로를 보존하는 매핑을 먼저 둔다. 과거 충돌 저장소 자동 병합이나 이름 변경을 위한 무조건적인 데이터 복사는 피한다.

Linux의 저장소 실패 경고와 임시 세션 fallback은 **이미 있다**. 남은 것은 영구/임시 상태를 작업 시작·상세 정보에서도 쉽게 확인하고 복구 후 새 프로필로 여는 동선이다. `Chrome`/`Firefox` 명칭은 실제 렌더러 교체나 로그인 가져오기를 뜻하지 않도록 표현을 정리한다. [Linux 구현](../crates/flowmux/src/ui/browser_pane_webkit.rs), [설정](../crates/flowmux-config/src/options.rs)

호스트 쿠키 가져오기는 현재 미지원이다. 우선 Flowmux 안에서 로그인한 프로필 재사용을 완성한다. 쿠키만 이전해도 passkey·SSO·IndexedDB·기기 결합 인증까지 재현된다고 약속하지 않는다. 인증 상태 파일 자체가 민감정보이므로 일반 결과물과 분리한다. [인증 상태 보관](https://playwright.dev/docs/auth)

### 재탐색과 입력 검증

첫 단계는 안정적인 영구 ref가 아니라 **읽기 전용 재탐색 도우미**다. 문서가 바뀌면 원래 role/name/label과 새 후보를 보여주고, 유일성이 확인된 새 ref를 반환한다. 후보가 여러 개면 선택을 요구한다. 입력 후 결과가 불명확할 때 재탐색만으로 동일 동작의 자동 반복을 허용하지 않는다.

현재 form의 문자열 일치 검증은 전화번호·날짜처럼 사이트가 입력을 포맷팅하면 `invalid`가 될 수 있다. 기존 엄격한 기본값을 유지하면서 요청별로 명시적인 최종 값/검증 조건을 지정하는 방식을 검토한다. 사이트 포맷팅을 무조건 허용하거나 성공 기준을 느슨하게 바꾸지 않는다. 준비 상태 확인과 업무 결과 확인은 별개다. [Actionability](https://playwright.dev/docs/actionability)

현재 WebDriver는 별도 임시 창을 만드는 경로이며 기존 pane에 붙는 API가 아니다. 따라서 이를 그대로 연결해 기존 탭의 백그라운드 자동화를 해결할 수 있다고 가정하지 않는다. 엔진 전환·외부 브라우저 연결은 실제로 막히는 사이트와 업무를 모은 뒤 호환성·배포·보안 업데이트 비용을 함께 판단한다.

## 6. 보안과 편의 기능을 함께 설계할 부분

이미 반영된 같은 OS 사용자 IPC 검사, 소켓 권한, task와 인증의 구분, 파일 선택 root 검증, password value 차단, 요청 출처 표시, 쿠키 미지원의 정직한 응답은 유지한다. 다음은 **새 기능을 추가할 때 필요한 경계 보완**이며, 이 검토에서 재현된 취약점 목록은 아니다.

| 범위 | 개선안 | 피해야 할 오해·완료 기준 |
| --- | --- | --- |
| 작업 권한 | 작업 생성에서 대상 사이트·프로필·파일 범위와 허용 동작을 보여준다. 상호작용/파일 제공처럼 영향 있는 단계의 추가 확인은 사용자가 정한 정책에 맞춘다. 범위가 바뀌었을 때만 재확인 | UI의 read-only 표시만으로 보안 경계가 생기지 않는다. 임의 eval, JS wait, 직접 IPC, shell 우회까지 포함하지 못한 정책은 편의 제어로 명시. 같은 사용자 권한의 임의 프로그램까지 막으려면 별도 실행 격리가 필요 |
| 로그인 편의 | 먼저 사람의 로그인/MFA 인계와 프로필 재사용. 이후 필요하면 origin·credential reference를 검증하는 비밀값 비노출 자동 채움 검토 | raw eval·캡처·일반 텍스트 추출 경로가 열린 상태에서 비밀번호가 모델에 절대 노출되지 않는다고 약속하지 않음. origin 변경·잠금·취소·다른 frame에 대한 거부 검증 |
| 결과 저장·내보내기 | raw receipt 대신 요약·확인 조건·시각·출처를 저장. URL query/fragment, 토큰·개인정보·로컬 경로의 노출 정책을 정하고 사용자가 공유 전 미리보기 | password 타입 차단은 일반 텍스트 비밀값·스크린샷의 자동 제거가 아니다. 로그/CSV/HTML/이미지별로 확인하고, CSV 수식 주입 및 HTML 활성 콘텐츠도 결과 내보내기 시 방어 |
| 파일 제공·열기 | 현재 canonical root·링크·특수 파일 제한 유지. 새 업로드 기능에서도 선택한 파일과 실제 제공 시점의 범위를 확인. 결과 미리보기는 기존 제한된 뷰어/asset 경로 재사용 | 파일 교체·심볼릭 링크 경쟁은 별도 재현 항목. 다운로드 완료가 안전한 실행 파일이라는 뜻은 아님. 파일은 자동 실행하지 않고 사용자가 열도록 유지 |
| 페이지 지침·반복 절차 | 페이지/파일 텍스트를 신뢰되지 않은 관찰값으로 표시. 페이지가 작업 범위·권한·템플릿을 스스로 바꾸지 못하게 한다. 저장된 절차는 사용자 검토와 출처 기록 | 프롬프트 문구만으로 방어 완료를 주장하지 않음. 읽기 중 발견한 지시가 파일 업로드·외부 전송·예약 작업 생성으로 승격되지 않는지 검사 |
| 권한 요청과 감사 | top-level과 요청 frame origin, 요청 종류, 허용/거부·취소 시각을 사용자 화면에 연결. Linux에서 모르는 frame origin은 추정하지 않음 | page dialog와 카메라/마이크 등 native 권한은 별개. 에이전트가 Continue나 확인 UI를 대신 승인하는 경로를 새로 만들지 않음 |

[IPC](../crates/flowmux-ipc/src/server.rs), [파일 선택](../crates/flowmux/src/ui/browser_file_chooser.rs), [제한된 editor asset 서버](../crates/flowmux-editor/src/web_assets.rs), [password 읽기 제한](../crates/flowmux-browser/src/scripts.rs)을 출발점으로 삼는다. 페이지 입력으로 도구 권한이 확대되는 위험과 최소 권한은 [OWASP Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/), [Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/), 내보내기 위험은 [CSV Injection](https://community.owasp.org/attacks/CSV_Injection)을 참고했다.

Flowmux가 로컬에서 브라우저를 실행하는 것과 에이전트가 snapshot·캡처·파일을 모델 제공자에 전송하는 것은 다른 데이터 흐름이다. 실제 사용하는 에이전트·모델 설정에 따라 전송될 수 있는 내용을 표시해야 한다. 프로필 공유도 단순한 실행 편의가 아니라 로그인 계정의 권한을 공유하는 선택임을 설명한다.

| 사용자가 다른 창에서 입력 | 입력이 엉뚱한 터미널/브라우저로 이동하지 않음 | macOS 가림/최소화, Linux X11 포커스 전환. Wayland는 별도 지원 판정 |
| 작업 저장 후 다시 열기 | 요약·파일은 복원되지만 입력은 자동 재생되지 않음 | 앱 재시작·파일 삭제·origin 변경·로그인 만료를 조합. 재개 시 새 snapshot 요구 |

측정값은 완료율, 잘못된 성공 보고, 중복 부작용, 사용자 개입 횟수, 작업 시간, 모델 왕복 수, 실제 출력/토큰량이다. 부분 snapshot의 문자 수 감소를 모델 비용이나 완료율 개선으로 곧바로 바꾸지 않는다. 공개 사이트 시연은 URL·확인 시각·최종 상태·결과물을 남기고, 파일 선택 창을 열었거나 입력 전달만 끝난 상태를 완료로 기록하지 않는다.

이번 분석에서 새 런타임 검사는 실행하지 않았다. 기준 커밋의 기존 [Test](https://github.com/flowmux-ai/flowmux/actions/runs/40111503973)와 [Sanitizers](https://github.com/flowmux-ai/flowmux/actions/runs/40111503956)는 앞선 구현 검증 기록이며, 위 신규 제안이나 경계 사례가 검증됐다는 뜻은 아니다.

## 8. 브라우저 탭 화면 구성 개선 계획

### 목표와 범위

대상은 터미널과 브라우저를 나란히 쓰는 Flowmux 사용자다. 목표는 **웹페이지를 넓게 보면서, 현재 작업 상태와 필요한 조작을 빠르게 찾는 화면**이다. 이미 있는 탐색·검색·북마크·다운로드·작업 제어·결과를 재배치한다. 앞 절의 표 추출·프로필 관리·결과 영구 보관·SDK는 이 UI 작업의 완료 조건에 포함하지 않는다.

계획 작성 시점(2026-10-25)에 실행 중인 macOS 앱에서 기존 브라우저 탭의 일반 탐색 화면을 직접 관찰했다. 탐색 후 원래 터미널 탭으로 돌아왔으며 페이지 탐색·작업 시작·앱 재시작은 하지 않았다. 설치 앱과 현재 소스의 빌드 일치는 검증하지 않았으므로, 화면 관찰과 `51160b68`의 코드 확인은 별도 근거다. Linux 실화면과 작업 실행·결과 표시 상태는 당시 직접 관찰하지 않았다. 구현 뒤 양쪽 검증 결과는 아래 구현·검증 기록에 별도로 남겼다.

### 현재 화면에서 바꿀 점

| 현재 구성과 근거 | 개선 방향 |
| --- | --- |
| 주소창 옆에 뒤로·앞으로·새로고침·북마크·검색·축소·배율·확대·다운로드·개발자 도구가 나열됨. macOS 실화면과 양쪽 플랫폼 코드에서 확인 | 자주 쓰는 탐색과 보조 도구를 분리. 버튼의 배경·크기·간격을 통일하고 주소창에 시선 집중 |
| 작업 바는 상태 설명과 Results, Take control, Continue, Stop task, Clear task를 같은 행에 배치. 설명은 여러 줄로 확장됨 | 한 줄 상태 요약과 상황별 주 행동 하나를 먼저 표시. 전체 설명과 결과는 펼치는 상세 영역에 배치 |
| 결과는 최대 높이 360의 팝오버, 다운로드와 북마크는 별도 팝오버 | 짧은 선택은 팝오버 유지. 작업 설명·결과처럼 읽으며 페이지와 대조하는 정보는 접을 수 있는 영역으로 이동 |
| 프로필과 저장 여부가 북마크 버튼 tooltip에 있음 | 더보기 안에 프로필 이름·영구/임시 상태를 명시. 관리·계정 전환 기능을 있는 것처럼 추가하지 않음 |
| pane의 탭 막대는 터미널·브라우저·에디터가 공유 | 브라우저 안에 중복 탭 막대를 만들지 않음. 공통 탭 높이·닫기·드래그 동작은 유지하고 브라우저 도구 모음과의 경계를 정돈 |

### 화면 방향과 구조

두 가지를 비교했다. A안은 도구를 더보기로 모으고 결과 팝오버를 그대로 두는 최소 변경, B안은 여기에 접을 수 있는 작업 상세 영역을 더하는 구성이다. **A안을 첫 단계로 적용하고 B안을 완성 화면으로 삼는다.** 항상 열린 오른쪽 패널은 분할 작업 공간을 좁히므로 채택하지 않는다. 별도 사이드바·새 탭 체계·큰 카드 대시보드도 추가하지 않는다.

일반 탐색에서는 기존 탭 막대 아래 도구 모음 한 줄만 보인다.

```text
[기존 pane 탭: 터미널 | 브라우저 | 에디터]
[뒤로][앞으로][새로고침] [주소                         ] [북마크][다운로드][더보기]
┌────────────────────────────────────────────────────────────────────────────┐
│ 웹페이지                                                                   │
└────────────────────────────────────────────────────────────────────────────┘
```

작업이 있을 때만 한 줄 요약이 추가된다. 예시는 기존 작업 정보가 제공된 경우이며, 없는 단계·진행률을 추정해 채우지 않는다.

```text
[뒤로][앞으로][새로고침] [주소                         ] [북마크][다운로드][더보기]
[작업 중 · 보고서 받기 / 파일 대기]              [직접 조작][중단][결과 2 ▸]
┌─────────────────────────────────────────────┬──────────────────────────────┐
│ 웹페이지                                    │ 작업 상세                [×] │
│                                             │ 보고서 받기                  │
│                                             │ 현재 단계 / 대기 이유        │
│                                             │ 결과                         │
│                                             │ 보고서.pdf · 다운로드 완료   │
│                                             │ [파일 열기] [폴더 열기]      │
└─────────────────────────────────────────────┴──────────────────────────────┘
```

상세 영역은 기본 닫힘이며 사용자가 열었을 때만 공간을 차지한다. 완료 알림이나 결과 추가로 자동 펼치지 않는다. 작업 상태를 작은 스트립 하나로 표현하는 것이 이 화면의 특징이다. 강조색은 현재 주 행동과 상태 표식에 집중하고, 페이지 주변은 기존 Flowmux 테마와 연결된 차분한 면으로 유지한다.

### 조작별 설계

| 영역 | 변경 내용 | 동작 기준 |
| --- | --- | --- |
| 탐색 도구 모음 | 뒤로·앞으로·새로고침은 평평한 아이콘 버튼. 주소창만 입력 영역으로 구분. 우측에 북마크·다운로드·더보기 | 사용 불가능한 뒤로/앞으로는 비활성. 기존 탐색 잠금·작업 소유권 제약 유지. 페이지 로딩과 자동화 작업 실행을 다른 상태로 표시 |

| 작업 상세 | 전체 작업명·단계·대기 이유·필요한 행동, 기존 결과 목록 제공 | 패널을 닫아도 작업·결과를 지우지 않음. Clear task는 종료된 작업의 “작업 표시 지우기”로 별도 제공하고 결과 표시도 지워진다는 설명 유지 |
| 결과 목록 | 종류 아이콘, 짧은 제목, 명시적 상태, 파일/폴더/관련 탭 열기. 부가 설명은 펼쳐 보기 | 입력 전달·조건 확인·실패·미확인을 다른 문구로 표시. 파일 선택과 업로드 확인을 구분. 새 결과가 와도 읽는 위치·키보드 포커스를 빼앗지 않음 |
| 다운로드·북마크 | 기존 팝오버를 같은 행 높이·여백·빈 상태 표현으로 정리 | 다운로드는 진행 중 취소, 완료 후 열기. 실패 상태에 이유 표시. 임의의 재시도·자동 열기 추가 없음 |
| 페이지 내 찾기 | 더보기에서 열고 페이지 상단의 작은 검색 행으로 표시. 닫기 동작 명확화 | 닫을 때 페이지로 포커스 복귀. 양쪽 엔진에서 실제 제공 가능한 결과 정보만 표시 |

### 크기·색·서체 기준

수치는 초기 설계 목표이며 GTK 논리 픽셀 기준이다. 접근성 글꼴 확대 시 높이는 늘어날 수 있고 고정 높이로 텍스트를 자르지 않는다.

- 도구 모음 목표 높이 44, 입력·버튼 높이 32, 아이콘 16, 간격 4/8/12. 버튼마다 진한 배경을 두지 않고 hover·pressed·focus 상태에서 구분한다.
- 작업 요약은 기본 32 높이, 작업이 없으면 숨김. 일반 탐색 시 상단 영역은 기존 pane 탭 막대와 도구 모음까지만 차지한다.
- pane 폭 900 이상은 우측 상세 영역 약 300~340, 그보다 좁으면 아래쪽 접이식 영역으로 배치한다. 아래 영역은 기본 최대 본문 높이의 40%로 시작하고 내부 스크롤을 사용한다. 창 높이가 작거나 글꼴이 커지면 접근 가능한 최소 높이를 우선한다.
- 480 폭에서 뒤로·앞으로·새로고침·주소·더보기는 유지하고, 북마크·다운로드 보조 진입점을 더보기로 이동한다. 진행 중 다운로드는 더보기의 접근 가능한 텍스트/표식으로 알린다. 더 좁은 폭에서는 안전한 줄바꿈을 허용하며 주소 입력과 중단 버튼을 잘라내지 않는다.
- 색은 `ResolvedTheme`의 배경·전경·강조색에서 파생한다. 예시 검토 팔레트는 바탕 `#24262D`, 입력 면 `#30343E`, 구분선 `#484E5A`, 본문 `#F1F3F7`, 보조 글자 `#AEB7C6`, 강조 `#99ABFF`. 이 값을 모든 테마에 하드코딩하지 않는다. 밝은 테마는 기존 토큰으로 대응한다.
- 제목/상태는 기존 UI sans 계열의 medium 13~14, 본문/버튼은 동일 계열 regular 13, 경로·진단만 기존 monospace 12를 사용한다. macOS 시스템 글꼴과 Linux 설정 글꼴·한글 fallback을 존중하며 새 폰트를 번들하지 않는다.
- 주소창·팝오버 모서리는 6~8, 내부 버튼은 4~6으로 정리한다. 그림자·테두리·강조색 중복을 줄이고, 상태는 색만이 아니라 아이콘·문구로 전달한다. 지속적인 깜박임은 사용하지 않는다.

### Linux/macOS 구현 경계

공통 GTK 도구 모음·작업 상세의 표시 규칙은 동일하게 적용한다. 양쪽 플랫폼에서 중복되는 도구 모음 조립만 작은 공통 컴포넌트로 묶을 수 있으며, 페이지 로드·native 입력·권한·프로필 처리는 기존 구현에 둔다. 이번 작업을 브라우저 엔진 추상화 개편으로 확대하지 않는다.

macOS는 GTK viewport에 맞춰 WKWebView를 배치하므로 상세 영역을 웹뷰 위에 덮는 방식보다 나란히 배치하는 방식을 우선한다. 개폐·분할 크기 변경 뒤 웹뷰 좌표·클릭 대상·IME·팝오버 가림을 검증한다. Linux는 WebKitGTK 위젯과 팝오버의 포커스·스크롤·배율을 확인한다. 도구 모음 CSS를 Linux 전용 분기에 넣지 않는다.

작업 실행 중 새 정보가 왔다는 이유로 웹뷰 크기를 자동 변경하지 않는다. 사용자의 상세 영역 개폐·창 크기 변경으로 좌표가 바뀌면 기존 입력 처리와 충돌하지 않도록 실제 native 입력 중 동작을 검증한다. 새 레이아웃이 배경 입력·Wayland native 입력 지원을 보장한다고 취급하지 않는다.

| UI-2 작업 상태 | 한 줄 요약과 상태별 버튼, 전체 설명 펼치기 | 작업 없음/실행/사용자 개입/일시정지/중단/완료에서 올바른 버튼 표시. 중단·계속·지우기의 기존 허용 조건 유지 |

실화면 완료 시나리오는 ① URL 입력 후 뒤로/앞으로 이동, ② 찾기·배율 변경·복구, ③ 작업을 직접 조작으로 전환하고 다시 계속, ④ 다운로드 완료 파일 열기, ⑤ 상세 영역을 열고 닫은 뒤 페이지의 한글 입력, ⑥ 다른 탭으로 갔다 돌아와 해당 탭의 상태만 보이는지 확인이다. 실행 중인 사용자 세션을 재시작하지 않고 별도 인스턴스에서 수행한다. 새로운 상태별 표시와 취소/재개 연결에는 집중 테스트를 두고, 여백 수치만 복제하는 테스트는 만들지 않는다.

UI-1~UI-4를 통과하면 이번 화면 개선은 종료한다. 신규 업무 기능, 전체 창/사이드바 리디자인, 엔진 교체, 보관 데이터베이스는 후속 조건으로 추가하지 않는다. 아래 구현 기록으로 UI-1~UI-4의 검증 상태를 관리한다.


### UI-1~UI-4 구현·검증 기록 (2026-10-25)

- UI-1: 양쪽 플랫폼이 `browser_chrome.rs`의 도구 모음을 사용한다. `browser.css`로 기본 버튼의 입체 배경·그림자를 제거하고, hover·focus·선택 상태와 주소창을 기존 테마 색에 맞췄다. 좁은 폭의 Bookmarks/Downloads, 검색·배율·개발자 도구는 Browser tools에서 접근한다. 편집 중인 주소 보호와 Enter 후 페이지 포커스도 반영했다.
- UI-2: 상태별 Take control/Continue/Stop을 표시하고 종료 뒤 Clear task display를 상세 영역에 둔다. 작업명·단계/대기 이유는 한 줄 요약, 전체 설명은 상세 영역에서 확인한다. 기존 task 소유권·취소·재개 조건은 유지했다.
- UI-3: 넓은 pane에는 약 320 폭의 오른쪽 영역, 좁은 pane에는 아래쪽 영역을 둔다. 결과에 종류 아이콘·상태·설명 펼치기·기존 열기 버튼을 배치한다. 새 결과가 패널을 자동으로 열지 않으며, 변경 없는 결과 행은 다시 만들지 않는다. 상세 영역 닫기는 작업/결과 삭제와 구분한다.
- UI-4: 실제 WebKitGTK/WKWebView를 생성하는 공통 검사에서 480/720/1200 폭, 밝음/어두움, 150%/200% 글꼴, 더보기의 다운로드 메뉴, 찾기 열기/닫기, 뒤로/앞으로, 배율 복구, 작업 인계/계속/중단/지우기, 탭 숨김·복귀, 패널을 닫은 후 native 클릭·한글 삽입을 확인한다. 앱 재시작이나 사용자 세션 종료 없이 별도 프로세스로 실행했다.

검증 중 발견해 수정한 항목은 우측 영역이 남는 폭을 과도하게 차지하던 설정, 숨겨진 부모의 가시성을 따라 검색 행이 열리지 않던 연결, macOS에서 찾기 종료 후 숨겨진 검색창에 포커스가 남아 탭 자원이 해제되지 않던 경로다. 패널 크기 전환 시 스크롤 높이의 이전 제한도 먼저 해제한다. 작업 UI는 공유 상태를 사용해 pane 구조의 크기 증가를 제한했다. macOS native 입력 검사는 기존 키보드 테스트처럼 AppKit 테스트 앱의 launch/activation 절차를 거치도록 했다. Linux VM에서는 기존 `flowmux-webkit` AppArmor 프로필로 실행하며 WebKit 샌드박스를 비활성화하지 않았다. 한글 시각 검증을 위해 VM에 `fonts-noto-cjk`를 설치했다.

검증 명령과 근거:

- macOS: `FLOWMUX_BROWSER_CHROME_SMOKE_ONLY=1 GSK_RENDERER=cairo cargo test -p flowmux --test macos_native --features native-smoke --locked` → `BROWSER_CONTROL_UI_OK`, `BROWSER_CHROME_LAYOUT_OK`, `MACOS_NATIVE_SMOKE_OK`.
- Linux/X11 VM: 기존 AppArmor 프로필 + Xvfb에서 `cargo test -p flowmux --bin flowmux browser_ -- --nocapture` → 최종 코드의 브라우저 관련 106개 통과. `browser_chrome_layout_and_controls`에 메뉴·탭 전환·패널 크기·한글 입력 검사를 포함한다.
- macOS 탭 종료: `FLOWMUX_BROWSER_LIFETIME_SMOKE_ONLY=1 GSK_RENDERER=cairo cargo test -p flowmux --test macos_native --features native-smoke --locked` → `MACOS_NATIVE_BROWSER_LIFETIME_OK`, `MACOS_NATIVE_SMOKE_OK`. GTK 검색창과 native 웹뷰의 자원 해제를 확인했다.
- macOS 별도 앱: `python3 scripts/test-browser-control.py target/debug/flowmux` → `BROWSER_CONTROL_OK`. 실제 다운로드 내용, 팝업·파일 선택, native 입력, frame/shadow, 캡처·녹화·미디어, task/receipt 회귀를 포함한다.
- macOS `cargo clippy -p flowmux --all-targets --features native-smoke --locked -- -D warnings`, Linux `cargo clippy -p flowmux --all-targets --locked -- -D warnings` 통과. `cargo fmt --all -- --check`, `git diff --check`와 CLI skill 관련 24개 테스트도 통과했다.
- 캡처는 `/tmp/fm-ui-macos/`, Linux VM의 `/tmp/fm-ui-linux/`에 저장한다. macOS GTK 렌더 캡처는 별도 native WKWebView 픽셀을 포함하지 않으므로 페이지 렌더 완료 증거로 사용하지 않는다. native 클릭·입력과 별도 앱 회귀 결과로 웹뷰 동작을 확인한다.

한계: Linux는 X11/Xvfb 검증이며 Wayland native 입력 지원을 새로 검증하거나 추가하지 않았다. native 한글 문자열 삽입은 확인했지만 OS 입력기의 실제 조합·후보 선택 전체를 자동화한 검사는 아니다. 결과 영구 보관·새 프로필 관리·자동 재시도는 추가하지 않았다.

### 개발자 도구 창 회귀 수정 (2026-10-25)

macOS에서 Developer tools를 열 때 Web Inspector가 WKWebView의 부모인 GTK 창 전체에 도킹해 터미널·도구 모음을 덮는 현상을 격리 앱에서 재현했다. 기존 검사는 `isVisible`만 확인해 잘못된 창 배치를 놓쳤다. 버튼 클릭 직후의 `detach`만으로는 비동기 연결 뒤의 도킹을 막을 수 없어, `_webView:didAttachLocalInspector:`에서도 연결된 도구를 분리한다. 분리 과정의 페이지 크기를 보존하고, 도구 안의 도킹 버튼으로 다시 붙여도 기존 frame 동기화 경로에서 별도 창으로 복귀시킨다. Linux는 기존에 별도 창으로 여는 경로를 사용한다.

- 수정 전: 개발자 도구와 브라우저의 native window가 같다는 회귀 검사 실패 및 실제 창 전체를 덮는 화면 확인.
- 수정 후: 별도 창, 도구 페이지 로드, 브라우저 크기·가시성 유지, 재도킹 후 창 분리, 닫기·재열기 및 탭 종료 시 자원 해제 검사 통과. 새 빌드의 실제 메뉴에서도 창 분리와 페이지 한글 입력을 확인했다.
- 근거: `/tmp/fm-inspector-regression-before.log`, `/tmp/fm-inspector-final.log`, `/tmp/fm-inspector-lifetime.log`.
- 구현 참고: [WebKit Inspector 연결·도킹 처리](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/Inspector/WebInspectorUIProxy.cpp), [macOS 도킹 시 부모 창 배치](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/Inspector/mac/WebInspectorUIProxyMac.mm).

### 주소 입력·탭 드래그·앞으로 버튼 회귀 수정 (2026-10-25)

- 앞으로 버튼: 좁은 pane에서 더보기로 옮기던 규칙을 제거했다. 뒤로·앞으로·새로고침은 항상 주소창 옆에 남는다. 수정 전 480px 표시 검사가 실패했고, 수정 후 macOS와 Linux의 480/720/1200px 검사 및 실제 뒤로·앞으로 탐색을 확인했다.
- macOS 한글 입력: 페이지 입력란에서 주소창으로 이동해도 AppKit의 입력 대상이 WKWebView에 남는 문제를 재현했다. 주소창과 페이지 찾기에 GTK 포커스가 들어오거나 다시 클릭하면 입력 대상을 GTK로 돌린다. 실제 두벌식 키 입력으로 페이지↔주소창을 세 번 왕복한 뒤 `한글` 조합, Enter 검색, 페이지 입력값 보존을 확인했다. 문자열 주입만으로 검증하지 않았다.
- macOS 탭 드래그: 좌표 기반 드래그 경로에 빠져 있던 미리보기 갱신을 연결했다. 기존 판정 기준으로 탭 삽입 위치와 오른쪽/아래/전체 영역을 표시하고, 브라우저 화면은 기존 캡처 기능으로 유지해 native 웹뷰가 표시를 가리지 않게 했다. 취소·종료·창 밖 이동 시 표시를 해제한다.
- 회귀 검사: `/tmp/fm-forward-before.log`, `/tmp/fm-address-before.log`의 수정 전 실패와 `/tmp/fm-chrome-final.log`, `/tmp/fm-browser-fixes-linux.log`, `/tmp/fm-drag-fixed.log`의 수정 후 통과. 드래그 표시의 반투명 픽셀 및 해제 검사를 실제 native 창에서 실행하고 `/tmp/fm-drag-check/`의 화면을 확인했다.
- 최종 검증: 전체 macOS native suite에서 드래그 미리보기, 브라우저·에디터·IPC, 대화상자, 저장 재시도, 개발자 도구를 포함해 `MACOS_NATIVE_SMOKE_OK`를 확인했다(`/tmp/fm-browser-fixes-native-full.log`). `cargo clippy -p flowmux --all-targets --features native-smoke --locked -- -D warnings`, 포맷과 diff 검사도 통과했다.

검증 범위: 한글 입력과 탐색은 별도 앱에서 직접 확인했다. 드래그 자동 조작 도구는 포인터 제스처를 전달하지 못해, 드래그는 native 창의 gesture 재현·렌더링 검사로 확인했다. 물리 마우스 드래그와 IME 후보 선택 전체는 확인하지 않았다. 설치된 앱이나 진행 중인 사용자 세션은 변경하지 않았다.
