# BU Bench V1 전체 100개 실행

**사용자 요청으로 중단됨:** 토큰 절약을 위해 배치와 실행·채점 모델 프로세스를 종료했다.
28개 채점 완료(성공 22, 실패 판정 6), 진행 중 3개 중단, 69개 미실행.
완료·중단 기록은 보존했으며 자동 재개하지 않는다. 아래 실행 중 설명은 중단 전 기록이다.

2026-10-28에 **100개 과제 전체 실행을 시작했다.** 이 문서는 실행 조건과
진행 파일을 설명한다. 완료된 벤치마크 성적표는 아니다. 배치 프로세스는 대화 응답과
독립적으로 실행되며, 모든 과제 판정이 모이면 전체 성공률을 자동 계산한다.

## 진행과 결과 위치

로컬 실행 디렉터리:
`/home/junsu/.local/state/flowmux/benchmarks/bu-v1-20261028-full-v2/`

| 파일 | 내용 |
| --- | --- |
| `status.json` | 전체·범주별 완료/채점/성공/실패 수, 토큰 사용량, 최종 성공률 |
| `config.json` | 모델·예산·과제 순서·데이터/바이너리/실행기 해시 |
| `batch.log` | 과제 시작·종료 로그 |
| `process.json` | 배치 프로세스 PID와 실행 명령 |
| `tasks/ID/state.json` | 개별 과제의 시작·실행·채점·완료 상태 |
| `tasks/ID/result.json` | 실행 결과와 별도 채점 결과 |
| `tasks/ID/browser.jsonl`, `screenshots/` | 명령·응답·스크린샷 |
| `tasks/ID/solver-events.jsonl`, `judge-events.jsonl` | Codex 구조화 이벤트와 사용량 |

`status.json`은 과제가 끝날 때 갱신된다. 시작 직후에는 개별 `state.json`과
`browser.jsonl`에서 진행을 확인할 수 있다. 일부 과제만 끝난 동안
`success_rate_percent`는 `null`이며, 미채점 과제를 0점으로 처리하지 않는다.
공급자 인증·쿼터 오류를 감지하면 나머지 과제 투입을 멈추고
`provider-blocked.json`과 `state: blocked_on_provider`를 남긴다.

복호화된 과제·정답·실행 증거가 들어갈 수 있어 원시 자료는 사용자 전용 디렉터리에
저장하고 저장소에 포함하지 않는다. 임시 디렉터리의 Python 환경을 사용하므로
재부팅·임시 파일 정리 후 자동 재시작을 보장하지 않는다.

현재 실행은 terminal pane 종료 후 브라우저 폭이 800px 이상이 될 때까지 기다린다.
GTK 초기 레이아웃·스크롤바 반영에 따라 초기 viewport 기록과 이후 PNG 크기는 달라질 수
있으므로, 고정된 브라우저 viewport나 경쟁 제품과 동일한 화면 조건을 주장하지 않는다.

실행 에이전트에는 과제 지시만 전달한다. 채점은 실행 종료 후 별도 컨텍스트에서
과제 지시·정답(있는 경우)·실제 명령 응답·최종 답변·마지막 고유 스크린샷 최대 10개를
사용한다. 원본 `judge.py`의 메시지 구성과 텍스트 길이 제한을 재사용한다.
에이전트의 `completed: true` 자체는 점수로 인정하지 않는다.

실제 구매, 타인에게 메시지 발송, 개인 계정 사용은 실행 범위에서 제외했다.
공개 테스트 페이지의 폼 제출과 가상 테스트 데이터는 허용한다. 해당 제한 때문에
완료하지 못한 과제가 있으면 결과에 남기며 전체 분모에서 임의로 빼지 않는다.

## 최초 배치의 프롬프트 오류와 재시작

14:16 KST에 시작한 `bu-v1-20261028-full`은 최종 답변에 증거·설명을 붙이라는
공통 지시가 있었다. 숫자 하나만 요구한 과제에서 정답에 설명이 붙어 형식 실패가
발생했고, 과제별 형식 지시와 공통 프롬프트의 충돌을 확인했다.
이 배치는 중단해 `SUPERSEDED.json`과 원래 기록을 보존했다. 중단된 과제 결과도
남아 있으므로 **이 배치의 성공·실패 수는 최종 성적에 사용하지 않는다.**

수정된 `full-v2`는 `final_answer`에 과제가 요구한 답만 넣고, 부가 설명·미확인 사항은
`blocker` 필드에 분리한다. 100개 전체를 새로 실행하며 이전 배치의 성공 건도
가져오지 않는다. 이 수정은 평가 실행기 프롬프트에만 해당하며 Flowmux 제품 변경은 없다.

## 검증과 해석 범위

[실행기](../scripts/benchmark-browser-agent.py)의 자체 검사로 미실행·미채점을
실패로 집계하지 않는지 확인했다. 실제 과제 1개에서 실행→스크린샷 기록→독립
Codex 채점이 연결되는 것도 확인했다. 이 사전 검증 실행은 본 배치에서 제외하고
100개 모두 새로운 프로필에서 실행한다. 이전 대화에서 수행한 수동 파일럿도 제외한다.

**산출될 점수는 `gpt-6-astra + Flowmux + Codex 대체 채점`의 성공률이다.**
공식 V1 기본 Gemini 채점이나 Aside·Browser Use 발표 수치와 같은 조건의 재현은 아니다.
모델, 채점기, 사이트 변화, 로그인 상태, 실행 예산의 차이가 포함된다.
브라우저 제어 기술만의 차이를 분리하려면 같은 모델·채점기로 다른 제어 경로도 실행해야 한다.

원시 기록은 후속 오류 분석과 공식 채점 재실행에 사용할 수 있다. 모델 사용량은
CLI가 보고한 값으로 저장하며 금액은 추정하지 않는다. 페이지 조작 제한은 에이전트
지침과 기록으로 관리하므로 최종 성능 분석 때 도구 사용 준수도 확인해야 한다.

Online-Mind2Web 300개는 이번 배치에 포함하지 않았다. 최초 확인한 데이터 접근 인증
문제는 [사전 확인 보고서](browser-agent-benchmark-preflight-20261028.ko.md)에 남아 있다.

## 중단 후 채점 입력 개선

저장소 실행기에 `complete-trajectory-v1` 증거 정책을 추가했다. 중단된 실행의
고정 `runner.py`, 원래 채점 입력·판정과 중단 상태는 변경하지 않았다.

기존 어댑터는 명령 응답을 전부 이어 붙였지만, 원본 채점기가 실행 기록을 앞에서부터
40,000자까지만 전달했다. 완료된 28건 중 **21건의 기존 채점 입력에서 잘림**을 확인했다.
후반 증거가 없다는 이유로 실패한 사례도 있었으므로, 원래 판정을 확정 성적으로
해석하기 전에 증거 완전성을 검토해야 한다. 잘렸다는 사실만으로 통과·실패가 뒤집히지는 않는다.

새 정책은 다음과 같다.

- snapshot/find의 JSON을 중첩 객체로 전달하고, 동일한 출력은 이전 단계 참조로 압축한다.
  모든 명령·출력 내용·오류·ref 정보·관찰 범위의 `truncated` 표시는 보존한다.
- 최종 답변 형식은 유지하면서 실행 에이전트의 `blocker`도 자기 보고임을 명시해 전달한다.
- 과제·최종 답변·전체 실행 기록 각각의 40,000자 제한을 검사한다. 한도를 넘으면
  채점 모델을 호출하지 않고 `score: null`, `review_required`로 보류한다.
  원본 메시지 구성 이후에도 각 텍스트 구간이 그대로 남아 있는지 확인한다.
- `judge-evidence.json`에 정책 버전·단계 수·입력 크기·보류 사유를 기록하고,
  결과와 집계에도 정책과 검토 사유를 남긴다. 성공 사례에도 동일하게 적용한다.

자체 회귀 검사와 저장된 28건의 오프라인 검증을 통과했다. 원본 명령·관찰·오류를
압축 표현에서 복원해 대조했고, 실제 원본 메시지 구성기를 사용하되 모델 실행은
대체 함수로 막았다. **8건은 전체 입력을 한도 안에 전달하고, 20건은 보류**한다.
문제가 된 154단계 사례는 압축 후에도 276,393자이므로 보류 대상이다.
긴 기록을 위한 별도 증거 처리 정책 없이는 이 사례를 자동 재채점할 수 없다.

이번 검증에서 브라우저 실행·유료 모델 호출·재채점은 하지 않았다. 기존 22건 성공·6건
실패 판정은 그대로이며, 개선 후 성공률은 아직 측정하지 않았다. 과거 28건을 재채점한다면
실패한 사례만 골라 고치지 말고 같은 정책을 전체에 적용해야 한다.
